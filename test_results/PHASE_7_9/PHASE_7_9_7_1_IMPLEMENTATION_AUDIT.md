## 1. Резюме для руководства

Проведён комплексный аудит существующей подсистемы `VillagerBrainThrottler` на уровне исходного кода и байт-кода относительно кодовых баз среды выполнения Minecraft 1.21.1 и NeoForge 21.1.265.

Архитектура предназначена для снижения частоты обработки неподвижных жителей (торговых стоек и кроватей) с 20 Гц до 5 Гц (`stallInterval = 4`) или 2 Гц (`bedInterval = 10`) при сохранении полной частоты обработки 20 Гц для срочных состояний (торговля, навигация, перемещение, урон, паника).

В ходе аудита верифицировано 13 ключевых инвариантов и выявлено **2 подтверждённых дефекта**:
1. **Разрыв в автодеактивации и глобальном переключателе:** `VillagerBrainThrottler.shouldTickBrain(Villager)` обходит `KtfConfig.isAutoDisabled()` и `KtfConfig.getEffectiveCommon().enabled()`.
2. **Циклическая задержка обнаружения враждебных сущностей (разбавление частоты сенсоров):** Поскольку `Sensor.timeToTick` уменьшается исключительно внутри `Brain.tick()`, троттлинг неподвижных жителей до 5 Гц разбавляет 20-тиковый интервал сенсора в 4 раза ($20 \times 4 = 80$ мировых тиков = 4.0 с), а интервал кровати — в 10 раз ($20 \times 10 = 200$ мировых тиков = 10.0 с), прежде чем `VillagerHostilesSensor` сможет активировать `Activity.PANIC`.

## 3. Подтверждённые дефекты и уязвимости

### Дефект 1: Обход автодеактивации и общего переключателя enabled
- **Файл:** `VillagerBrainThrottler.java:28-32`
- **Первопричина:**
  ```java
  public static boolean shouldTickBrain(Villager villager) {
      EffectiveServer cfg = KtfConfig.getEffectiveServer();
      return shouldTickBrain(villager, cfg.villagerThrottlingEnabled(),
              cfg.villagerStallInterval(), cfg.villagerBedInterval());
  }
  ```
  `IdleChecker` строго соблюдает `!KtfConfig.getEffectiveCommon().enabled()` и `KtfConfig.isAutoDisabled()`. В отличие от него, `VillagerBrainThrottler` никогда не проверяет эти условия.
- **Последствие:** Если TPS сервера падает и срабатывает схема динамической автодеактивации, либо если пользователь устанавливает `common.enabled = false`, жители остаются под троттлингом.
- **Требуемое исправление:** Добавить явную защиту в `shouldTickBrain(Villager)`:
  ```java
  if (!KtfConfig.getEffectiveCommon().enabled() || KtfConfig.isAutoDisabled()) {
      return true;
  }
  ```

### Дефект 2: Разбавление сенсора обнаружения враждебных сущностей (цикличность)
- **Файл:** `VillagerBrainThrottler.java:45` и `net.minecraft.world.entity.ai.sensing.Sensor.java:38`
- **Первопричина:**
  В Minecraft 1.21.1:
  ```java
  // Sensor.java
  public final void tick(ServerLevel level, E entity) {
      if (--this.timeToTick <= 0L) {
          this.timeToTick = (long)this.scanRate;
          this.doTick(level, entity);
      }
  }
  ```
  `Sensor.tick()` вызывается исключительно внутри `Brain.tick()`.
  Когда неподвижный житель троттлится до 5 Гц (`stallInterval = 4`), `Sensor.tick()` вызывается один раз каждые 4 мировых тика.
  Поскольку `--this.timeToTick` уменьшается только на 1 за вызов Brain:
  - Ванильный режим: 20 уменьшений $\times$ 1 тик = 20 мировых тиков (1.0 с).
  - Троттлинг (Stall = 4): 20 уменьшений $\times$ 4 тика = **80 мировых тиков (4.0 с)**.
  - Троттлинг (Bed = 10): 20 уменьшений $\times$ 10 тиков = **200 мировых тиков (10.0 с)**.
  Пока `VillagerHostilesSensor` не выполнит свой `doTick()`, `MemoryModuleType.NEAREST_HOSTILE` не заполняется.
  `VillagerPanicTrigger` не может активировать `Activity.PANIC`.
  `VillagerBrainThrottler` проверяет только `brain.isActive(Activity.PANIC)`.
  Следовательно, неподвижный житель остаётся под троттлингом до 4.0 секунд, пока зомби приближается.
- **Требуемое исправление:** Устранить разбавление частоты сенсора либо добавить прямое O(1) распознавание памяти / угрозы без введения дорогостоящих глобальных сканирований сущностей.

## 4. Нерешённые неопределённости (рассматриваются в последующих фазах)
1. **WorkAtPoi: мировое время против вызовов Brain (Фаза 7.9.7.3):**
   Аудит `WorkAtPoi.java` подтвердил, что он полагается на `level.getGameTime() - this.lastCheck < 300L`. Поскольку `level.getGameTime()` инкрементируется каждый мировой тик, 300-тиковый кулдаун основан на мировом времени. Однако требуется внутриигровая верификация для измерения эмпирического времени пополнения запасов в условиях троттлинга.
2. **Эмпирическая задержка реакции на враждебные сущности (Фаза 7.9.7.2):**
   Подтвердить эмпирическую задержку реакции на выделенном сервере и проверить, что исправление по усилению восстанавливает стандартное время реакции на угрозу без регрессии MSPT.
