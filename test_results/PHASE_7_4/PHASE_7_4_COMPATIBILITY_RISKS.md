# Фаза 7.4 — Совместимость с модами и оценка рисков

**Проект:** KilllTheFrizz  
**Платформа:** Minecraft 1.21.1 / NeoForge 21.1.265 / Java 21  
**Стандарты:** `mixin-safety-audit`, `mc-game-logic-guard`  

Данный документ описывает анализ потенциальных конфликтов архитектуры Phase 7.4 с популярными оптимизационными и контентными модами экосистемы NeoForge 1.21.1.

---

## 1. Совместимость с оптимизационными модами

### 1. Lithium / Radon / Canary
- **Зона пересечения:** Оптимизация коллизий сущностей (`pushEntities`), AI goal ticking, chunk tracking.
- **Риск:** Lithium заменяет ванильную коллекцию коллизий чанка на собственный пространственный кэш. Если KillTheFrizz отменяет вызов `move()` целиком через `@Inject(cancellable=true)`, кэш коллизий Lithium может рассинхронизироваться при неожиданном перемещении моба.
- **Стратегия защиты:** 
  1. Использование `@WrapOperation` из библиотеки `MixinExtras` вместо жесткой отмены. Это позволяет Lithium оборачивать вызов в свою очередь, сохраняя внутренние инварианты.
  2. Запрет изменения позиции `(x, y, z)` сущности во время `Physics Sleep`. Если моб получает внешний сдвиг, он немедленно просыпается с вызовом оригинального `move()`.

### 2. FerriteCore
- **Зона пересечения:** Сжатие CompoundTag и дедупликация структур памяти.
- **Риск:** Практически отсутствует. KillTheFrizz Phase 7.4 не изменяет формат сохранения NBT мобов.
- **Статус:** Полная совместимость.

### 3. Sodium / Embeddium / Iris
- **Зона пересечения:** Рендеринг и клиентское отсечение сущностей.
- **Риск:** Если сервер переводит моба в `Physics Sleep` и обнуляет `deltaMovement`, клиентский рендерер интерполяции (`lerpSteps`) должен плавно завершить шаг без рывков ("stuttering").
- **Стратегия защиты:** Сервер продолжает синхронизировать позицию моба при переходе в сон; интерполяция на клиенте завершается штатно.

## 4. Совместимость с контентными AI-модами

### 1. Alex's Mobs, Ice and Fire, Mowzie's Mobs
- **Зона пересечения:** Пользовательские классы сущностей с кастомным поиском путей (`AdvancedPathNavigate`), анимациями GeckoLib и сложными стейт-машинами.
- **Риск:** Кастомные мобы могут переопределять `customServerAiStep()` или вызывать навигацию напрямую из других методов.
- **Стратегия защиты:**
  1. **Strict Namespace Guard:** По умолчанию `AI Sleep` и `Physics Sleep` применяются **только к сущностям пространства имён `minecraft:`**.
  2. Все сущности сторонних модов (например, `alexsmobs:*`) по умолчанию попадают в статус `BLACKLISTED`, пока явно не включены пользователем в конфигурационный whitelist.

### 2. Easy Villagers / More Villagers / MCA Reborn
- **Зона пересечения:** Изменение искусственного интеллекта жителей (`Villager`), перехват торговли и инвентарей.
- **Риск:** MCA Reborn полностью заменяет `Villager` на собственный класс `HumanoidEntity`.
- **Стратегия защиты:**
  Инъекции в `Villager.customServerAiStep()` выполняются строго с таргетом на ванильный класс. Если житель подменяется сторонним классом, инъекция просто не срабатывает, не вызывая краша (`require = 0`).

## 3. Критические игровые инварианты (Game Logic Guard)

| Игровой механизм | Потенциальный риск Phase 7.4 | Механизм защиты в архитектуре |
|---|---|---|
| **Max Entity Cramming** | Отключение урона от удушья в переполненном загоне | Расчёт `maxEntityCramming` в `pushEntities()` выполняется **до** фильтрации взаимного расталкивания. При скоплении > 24 мобов коровы продолжают получать урон от сдавливания. |
| **Vanilla Despawn (32-128 блоков)** | Мобы зависают навечно в спящем состоянии | При пропуске `serverAiStep()` ручной инкремент `noActionTime++` сохраняется; ванильный деспавн работает бесперебойно. |
| **Разрушение блоков под мобом** | Моб зависает в воздухе ("floating mob") | `BlockEvent.NeighborNotifyEvent` прослушивает блоки. При удалении блока под спящим мобом флаг `Physics Rest` мгновенно сбрасывается. |
| **Поршни и слизь (Piston Physics)** | Поршень не может сдвинуть спящего моба | Вызов `pistonMove` инжектирует импульс напрямую в координаты, сбрасывая состояние покоя. |

## 4. Модульные аварийные рубильники (Config Safeguards)

Каждая из пяти подсистем Phase 7.4 должна управляться независимым переключателем в `killthefrizz-server.toml`:

```toml
[aiSleep]
enabled = true
throttleVillagerBrain = true
throttleSensors = true

[physicsSleep]
enabled = true
dampMutualPush = true
bypassStationaryMove = true

[adaptiveController]
enabled = true
minMsptForDeepSleep = 40.0
```

При возникновении конфликта с редким модом администратор сервера может точечно отключить проблемную подсистему (например, `physicsSleep.dampMutualPush = false`) без отключения остального мода.
