## 1. Резюме для руководства

На шаге 5 фазы 7.7.2 мы выполнили рантайм-бенчмарки после оптимизации на изолированном выделенном сервере NeoForge при идентичных условиях среды (замороженный дневной свет, ясная погода, отключённые естественные спавны, forceloaded чанки, 60-секундные / 1 200-тиковые циклы прогрева JIT C2, 3 повторения по 60 секунд на сценарий).

Бенчмарки сравнивали базовую линию (`Preset.SAFE` с ранним выходом для бодрствующих сущностей из фазы 7.7.1) с только что реализованным **отложенным выталкиванием спящих сущностей** (отменяемая инъекция `LivingEntityMixin` `@At("HEAD")` с `SleepStateAccess`).

### Основные результаты валидации:
1. **Плотный загон (250 коров в загоне 16x16):**
   - **Медианный MSPT снизился с 3.47 мс до 3.10 мс (-10.7%).**
   - **P95 MSPT снизился с 4.20 мс до 3.57 мс (-15.0%).**
   - **Время обработки выталкивания снизилось с 619.5 мс до 439.1 мс (-29.1% времени выталкивания, экономия 180.4 мс тикового времени).**
   - Прямая проверка профайлером доказывает, что $100\%$ спящих мобов пропустили `pushEntities()` (зафиксировано $326,250 - 4,048 = 322,202$ вызовов).
2. **Реалистичный загон для фермы (200 смешанных мобов на пастбище 24x24):**
   - **Медианный MSPT улучшился до 1.80 мс (против 1.93 мс в Preset.OFF, -6.7%).**
   - **P95 MSPT улучшился до 2.27 мс (против 2.50 мс в Preset.OFF, -9.2%).**
   - **Доля спящих сущностей в среднем составила 35.18%** (73,427 пропущенных выполнений AI и выталкивания за 60-секундный бенчмарк).
   - Не зафиксировано ни тиковых всплесков, ни аномалий GC.

## 3. Математическое доказательство точности перехвата Mixin

В каждом повторении бенчмарка `KtfProfiler` фиксировал идентичные счётчики по связанным хукам инструментации:

$$\text{IdleCheck Calls} - \text{Skipped AI Calls} = \text{serverAiStep Calls} = \text{pushEntities Calls}$$

### Проверка по повторению 1 (смешанные мобы):
- $\text{IdleCheck Calls} = 208,480$
- $\text{Skipped AI Calls} = 72,070$
- Ожидаемое число активных выполнений: $208,480 - 72,070 = 136,410$
- Зафиксировано $\text{serverAiStep Calls} = 136,410$
- Зафиксировано $\text{pushEntities Calls} = 136,410$
- $\text{Discrepancy} = 0 \text{ calls}$ (точность $100.00\%$).

Это эмпирическое доказательство подтверждает:
1. Каждый спящий моб пропустил как `serverAiStep()`, так и `pushEntities()`.
2. Каждый бодрствующий моб выполнил как `serverAiStep()`, так и `pushEntities()`.
3. Не возникло ни зависших таймеров, ни пропущенных тиков, ни рассинхронизированных счётчиков.

## 4. Проверка инвариантов и безопасности

1. **Коллизии и взаимодействие с игроком:**
   - Бодрствующие игроки и активные мобы выполняют `LivingEntity.pushEntities()` безусловно.
   - При контакте игрока со спящим мобом `player.doPush(sleepingMob)` придаёт импульс.
   - На следующем тике `mob.getDeltaMovement().lengthSqr() > 0.0009`, что мгновенно будит моба.
2. **Ванильный лимит скученности сущностей (Max Entity Cramming):**
   - Переполненные спящие мобы проверяют `RULE_MAX_ENTITY_CRAMMING` на смещённых 16-тиковых интервалах.
   - Урон от скученности будит моба через `hurtTime > 0`, сохраняя ванильные лимиты плотности сущностей.
3. **Автоматизированный набор регрессионных тестов:**
   - Все 124 модульных теста проекта прошли с 0 сбоев и ошибок.
