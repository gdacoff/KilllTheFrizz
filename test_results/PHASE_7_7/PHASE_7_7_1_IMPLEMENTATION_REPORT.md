# Отчёт о реализации Phase 7.7.1: Оптимизация горячего пути бодрствующих сущностей

## 1. Резюме для руководства

- **Проект:** KillTheFrizz
- **Модуль:** SleepingEntities (`IdleChecker.java`, `AwakeHotPathOptimizationTest.java`)
- **Платформа:** Minecraft 1.21.1 / NeoForge 21.1.265 / Java 21
- **Целевая проблема:** Бодрствующие мобы ранее выполняли полную логику проверки пригодности ко сну каждый тик (включая дорогостоящий поиск расстояния до игрока `hasNearbyAlivePlayer`, проверки типов сущностей и запросы к реестру), что приводило к избыточным накладным расходам CPU в активных окружениях.
- **Решение:** Введён побитовый ранний выход в `IdleChecker.shouldSleep()` для бодрствующих мобов (`!wasSleeping && !evalTick`), ограничивающий полные проверки пригодности ко сну выполнением раз в 16 тиков (`((tickCount + id) & 15) == 0`).
- **Статус реализации:** Проверено, 114/114 модульных тестов проходят, регрессий нет.

## 2. Изменённые и созданные файлы

### A. Изменённый production-код
1. **`src/main/java/io/github/gdacoff/killthefrizz/sleeping/IdleChecker.java`**
   - Добавлен ранний выход сразу после глобальных kill switch и перед проверками пробуждения на каждом тике:
     ```java
     // 1b. Awake entity hot path early exit (Phase 7.7.1).
     // Awake mobs only evaluate sleep eligibility once every 16 ticks.
     // On intermediate ticks, skip all wake/sleep checks and return false immediately (remain awake).
     boolean evalTick = isAwakeEvalTick(mob.tickCount, mob.getId());
     if (!wasSleeping && !evalTick) {
         return false;
     }
     ```
   - Добавлен публичный статический математический вспомогательный метод для детерминированного тестирования:
     ```java
     public static boolean isAwakeEvalTick(int tickCount, int entityId) {
         return ((tickCount + entityId) & 15) == 0;
     }
     ```

### B. Созданный набор тестов
2. **`src/test/java/io/github/gdacoff/killthefrizz/sleeping/AwakeHotPathOptimizationTest.java`**
   - 10 автоматизированных тестовых сценариев, покрывающих арифметику, переходы конечного автомата, события пробуждения и граничные случаи.

## 3. Инварианты и верификация безопасности

| Инвариант | Механизм реализации | Результат верификации |
|---|---|---|
| **Спящие мобы проверяются каждый тик** | Ранний выход требует `!wasSleeping`. При `wasSleeping == true` ранний выход полностью обходится. | Спящие мобы продолжают выполнять дешёвые проверки пробуждения (урон, навигация, скорость, цель, взрыв) на каждом тике. |
| **Бодрствующие мобы оцениваются с распределением** | Ограничено условием `((mob.tickCount + mob.getId()) & 15) == 0`. | Оценка выполняется ровно раз в 16 тиков (равномерно распределено по всем 16 фазам на основе ID сущности). |
| **Отсутствие прерывания ванильного AI** | Возврат `false` из `shouldSleep()` гарантирует, что `MobMixin` никогда не вызывает `ci.cancel()`. | Моб продолжает нормальный поиск пути, выполнение целей и сенсорные обновления без прерываний. |
| **Согласованность `ktf$wasSleeping`** | `MobMixin` присваивает `this.ktf$wasSleeping = sleep` (что равно `false` при раннем выходе). | Состояние корректно отражает, что моб бодрствует. |
| **Отзывчивость на урон и пробуждение** | Спящие мобы проверяют `hurtTime > 0` и `isForceAwake` каждый тик. | Мобы пробуждаются немедленно при получении урона, звуке взрыва или изменении блоков. |
| **Отсутствие «залипания» сна после пробуждения** | После пробуждения `wasSleeping` становится `false`. Моб останется бодрствующим как минимум до следующего eval-тика. | Предотвращает быстрые колебания («дребезг») между состояниями сна и бодрствования. |
